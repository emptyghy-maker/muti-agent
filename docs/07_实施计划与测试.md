## 2. 测试计划

### 单元测试（重点：规则引擎与白名单校验）
| 目标 | 断言要点 |
|---|---|
| `GeoUtils` | 已知两坐标距离误差 < 1%；同点距离为 0 |
| `FatigueScorer` | 强度×时长+交通公式正确；阈值判定；前后天联动插入休息点 |
| `MealTimeChecker` | 饭点窗口内无餐厅 → 返回待插入餐点；有餐厅 → 不插 |
| `BudgetCalculator` | 门票+餐饮+酒店+交通汇总；超支额与建议正确 |
| `SimpleRoutePlanner` | <1km 步行、1~8km 公交、>8km 打车；耗时费用按规则 |
| `CandidateService` 白名单 | LLM 返回非法 id 时被剔除/报错（mock LLM 输出含编造 id） |
| `TravelState` | 状态推进与回溯正确；非法跳转被拒；askedFields 拦截重复提问（nextQuestion 指向已确认字段时丢弃换下一个） |
| `DefaultsResolver` | 模糊字段按规则填默认值；预算 = 人均参考区间中位数 × 天数 × 人数 |

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 编造地点名/价格（幻觉） | 候选一律来自库 + id 白名单校验；提示词明令「只可用给定 id」 |
| LLM 违背饭点/疲劳硬约束 | 硬约束由规则引擎计算并注入骨架，LLM 只组织文本；解析后由 Java 再校验（餐点存在性） |
| 多轮会话丢失（Redis 过期/重启） | TTL 2h + 前端提示重新开始；关键结果及时落库 |
| LLM 输出 JSON 格式不稳 | 提示词强制格式 + Java 解析容错（旧项目 chartConfig 教训）；失败重试 1 次后降级规则结果 |
| LLM 重复提问惹烦用户 | 字段三态 + askedFields + Java 规则兜底；PreferenceAgent 用 plus 提升解析准确率 |
| 预算反复迭代烧 token | 默认预算参考区间一次通过；修改走 ADJUST 局部重生成；regenerate 上限 2 次 |
| 流式生成中断 | SSE onerror 处理沿用；行程结构化 plan 与文本独立，文本中断不影响时间线 |
| 种子数据工作量 | 南京/苏州两城先行，跑通并收集反馈后再扩容；数据造数脚本化 |
