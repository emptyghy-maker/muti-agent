# Observability 指标口径（DEV-01 契约）

依据开发文档 §5.1/§9 与 P2 手册 §4。新模块指标由后端统一计算，前端只展示；本口径不改动 UsageService 原 costOf 算法与旧页面费用定义。

## 1. 完成率

- 分子：businessStatus=COMMITTED 的**逻辑操作数**（operationId 去重）。
- 分母：进入记录的逻辑操作数（operationId 去重；失败、取消计入）。
- 幂等重放（REPLAY）不新增分母。
- 在途/等待单列 inFlightCount，不悄悄并入分母。

## 2. 费用与单位成本

- 总费用 = 全部已知费用（含失败与真实重试）之和；未知尝试单列 unknownCostCount，costComplete=false。
- 成功单位成本 = 已知总费用 / 成功计划数；成功数为 0 时为 null，不显示 0。
- 每次尝试记录时固化价格快照（priceSnapshot JSON + 币种 CNY + amountStatus）；改配置不影响历史。
- LEGACY 来源按当前价估算并标 LEGACY_ESTIMATE，与 NEW 分区展示，不合并成“总成本完整”。
- 新表与旧表不直接 UNION ALL 后统计同一请求费用。

## 3. token

- UNKNOWN → null 显示；KNOWN=0 → 0；工具无 token → NOT_APPLICABLE。
- 父 span 总量不再次相加子 span（避免双计）。

## 4. 耗时

- 墙钟 operationWallMs：run 的 endedAt-startedAt（业务时间）。
- 并行总工作量 providerWorkMs：span durationMs 求和（不等于墙钟）。
- 用户等待 waitMs：用户确认前等待区间（有事件时计算），单列，不并入模型时间。
- 队列等待 queueMs 有事件时展示，无则 null。

## 5. 展示要求

所有比率同时展示分子/分母；未知数据与旧来源在 API 与页面显式标注；不伪造完整性（dataCompleteness=PARTIAL 时页面标“部分数据”）。
