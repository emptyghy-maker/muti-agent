# Observability 埋点清单与来源（DEV-01 契约，对应开发文档 §7.4）

所有埋点均为「可空注入 + 无副作用事件」：模块关闭时 recorder 为 Noop，业务零开销；事件构建失败不向业务传播。

## 1. TraceService 既有边界（主要出口）

| 边界 | 事件 | 来源文件/方法 |
| --- | --- | --- |
| 注册 span | SPAN_STARTED | trace/TraceService.register |
| 结束 span | SPAN_FINISHED（OPERATION 根另发 OPERATION_FINISHED + usage attempts） | trace/TraceService.finish |

快照不可变（TraceEnvelope），不把活 TraceContext 引用放进异步队列。

## 2. 业务薄埋点（§7.4 白名单，仅追加无副作用事件）

| 文件 | 埋点 | 事件 |
| --- | --- | --- |
| TravelOrchestrator | 操作开始/结束、plan 节点开始/结束、用户确认、取消观察 | OPERATION_STARTED/OPERATION_ENDED、NODE_STARTED/NODE_ENDED、USER_CONFIRMED、CANCELLED、COMMIT_RESULT |
| CandidateService | 召回/过滤数量、已执行筛选结果、refine 节点生命周期 | NODE_STARTED/NODE_ENDED（summary: recallCount/filteredCount/acceptedByOrigin、businessStatus） |
| ItineraryService | 校验结果、修复轮次、patch 提议/拒绝、提交返回 | VALIDATION、REPAIR_ROUND、PATCH_PROPOSED/PATCH_REJECTED、COMMIT_RESULT |
| RouteFactService / FactToolService | 缓存命中、调用参数摘要、提供方结果/错误 | TOOL_CALL（external=true/false）、TOOL_REJECTED |

## 3. 约束

- 不得为了收集“判断理由”增加模型调用；没有显式理由就标“未提供”。
- 能从既有返回获得的信息不侵入下一层实现。
- 保持：阶段判断、确认语义、候选内容/排序/锁定/游标、规划输入/规则/修复次数/返回值、参数/超时/回退/工具执行次数——全部原样。
