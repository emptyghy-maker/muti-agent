# Observability 发布与回退说明（DEV-09）

## 发布顺序

1. **迁移**：执行 `sql/observability/001_core_schema.sql` 与 `002_tasks_experiments.sql`（只新增 obs_ 表；不修改任何业务表）。核验表与索引。
2. **后端（默认关闭）**：部署后端，`observability.enabled=false` 装配 noop，验证旧业务正常（P0/P1/P2 回归）。
3. **小范围开启采集**：`observability.enabled=true`、`observability.capture.enabled=true`，观察缓冲/批写/覆盖与业务不变性。
4. **开放查询与管理界面**：先 ADMIN（导航显示），再按范围开放普通用户简化视图。
5. **核对价格快照/脱敏/导出/保留期**，通过后扩大采集范围。

## 回退

- 优先关闭开关：`observability.enabled=false`（API 返回明确不可用语义；采集全 noop），保留 obs_ 表与证据。
- 前端：移除 App.vue 导航项即可（路由分支无副作用）。
- 不得通过删除全部表实现应用回退；旧代码不依赖新表，可回到原版本。
- 已持久化事件与待处理队列按协议恢复，无法恢复部分显式标缺失（dataCompleteness=PARTIAL）。

## 备份与清理

- 备份：obs_ 数据独立于业务库表，随 data_agent 常规备份即可。
- 清理：`ObsRetentionJob.purge(retentionDays)` 只处理 obs_payload（过期内容置 NULL + EXPIRED 摘要保留）；不清理业务表、P0 幂等记录、项目报告目录。
- 导出：`POST /api/v1/observability/exports` ADMIN 受控脱敏导出（摘要口径，无原文），动作入 obs_audit；CSV 公式前缀防护。

## 已知边界（如实列出）

- 原文载荷第一版关闭（/payloads 返回元数据，contentClosed=true）。
- 无 outbox：对账来源标 RECONCILED，工具原始 IO 与未持久化分支保留缺口（PARTIAL）。
- 未接入官方门禁：验收为单测 + suggestion/observability 桥接冒烟 + 上游 P0/P1/P2 重验。
- 事件游标仅表示接收顺序，不声称跨主机严格因果。
